## 1. What we are building

Fairflow is an academic serious game about distributive justice in water allocation, built at IHE Delft as the entry point of the EquiNex suite.

**How a game runs:**
- Three irrigation schemes in a river basin, each played by one player, and a basin Authority share a river and an aquifer over five or six seasons, each season one irrigation year.
- Each season the table votes on which principle of justice (a "lens") splits the river water.
- Each scheme then decides privately how much groundwater to pump and whether to invest (Orchard, Drip, Expand).
- The table is scored together on equity, efficiency and sustainability, and each scheme separately on livelihood.

**The proposition it must make felt:** there is no lens-free way to share scarce water.
- **UX idea:** the vote moves equity, the pumps move sustainability, and the reveal tells both as one story.
- **Facilitation idea:** play for an hour, then write the rule you wish you had had.

**The session lasts 120 minutes (ADR 0001):**
- play, at most 80 minutes, with a facilitator time-box;
- debrief, 25 minutes;
- deliberation on institutional design, 15 minutes;
- logistics, 15 minutes.

**Primary mode is room mode:** each player joins by QR code on their own phone, and a Python server runs the engine. One-phone offline table mode is a fallback that is not built yet.

## 2. Rules for anyone building on this (non-negotiable)

These come from the maintainer. Breaking them is a defect, not a style choice.

1. **Numbers come from Python, never from the model writing the code.**
   - Every calculation is done by a Python script or by the engine.
   - Every equation and value comes from the blueprint, a decision record, the parameter registry or the maintainer.
   - No arithmetic done in your head ends up in code, docs or answers.
2. **No unsourced numeric literal.**
   - `tests/test_no_unsourced_numbers.py` fails on a bare literal in engine code.
   - A tolerance or rounding constant needs a comment that says so (`# tolerance: …`, `# rounding: …`, `# layout: …`).
   - Model parameters have no default in code. They live in `packages/scenarios/parameters.json`, each with a verbatim blueprint quote that CI looks for in the blueprint.
3. **The blueprint is executable.**
   - Engine tests parse expected values out of `docs/blueprint.md` §3 (`tests/blueprint.py`, `bp.grab(...)`).
   - §3 is generated by an independent reference implementation, `analysis/reference_model.py`, written from the specification without reading the engine.
   - When the model changes, regenerate §3 from that script and let the engine tests compare.
   - A result that contradicts the blueprint is reported as a finding, never silently "fixed".
4. **One hypothetical basin, the Kelvara basin.**
   - Its numbers are typical literature values or labelled teaching conventions.
   - Never mix real places, real schemes or numbers from specific papers into it.
   - Real cases (Balotra, Mwea, Omo–Gibe) appear only as separate, labelled examples.
5. **Never mention WAFLEX** anywhere in Fairflow. Cite primary sources only, verified (DOI or publisher page), and only where a citation is really needed.
6. **Correctness first.** This is a scientific instrument.
   - Prefer stopping and documenting an open question over guessing.
   - Never tune the game or the display to pass a criterion. Balance and privacy gates measure; they are not targets to fit.
7. **Decisions go in a decision record** (`docs/decisions/NNNN-*.md`): context, decision, consequences, sources, and status with who accepted it and when. Value judgements, legal and ethics choices, and thresholds belong to the maintainer: propose them, don't decide them.
8. **Privacy is part of the design.** Per-scheme water, adequacy, yield, livelihood and pumping never reach any other screen during play (§9.1 privacy test; ADR 0004). New events need a visibility class, and new projections need a privacy test.
9. **Licensing.**
   - Every file carries an SPDX header: MIT for code, CC BY 4.0 for docs, content, scenarios and fixtures (see `REUSE.toml`).
   - `reuse lint` runs in CI.
10. **Before every push, run `bash scripts/check-all.sh`.** It runs exactly what CI runs.
    - `main` is protected, but an admin push bypasses it, so this script is the only gate.
    - Commits are small and descriptive, and pushed only when asked.

**The data flow, which every number follows:**
1. A phone sends an intent, for example `{intent: "commit", pumps: 2, action: "drip"}`.
2. The server takes the room lock and calls `Game.submit(role, intent, **args)`.
3. The engine validates the intent. A refused intent raises a typed `Rejection` and leaves the record unchanged.
4. An accepted intent appends events, each with a visibility class.
5. The server sends each connection `project(events, viewer)`.
6. The UI folds the projection with `viewOf` and renders it.

Only the engine computes model numbers. The UI formats and displays them.

## 4. The model in brief

**Wording.** The three seats are irrigation schemes in a river basin, not farms: B, for example, is a 900 ha cooperative with more than 5,000 people living from it. Write "irrigation scheme" (or "scheme" once that is clear) on screens, in documents, in data and in comments. Names such as "Tail-end Wheat Farms" are scheme names and stay. Accepted decision records keep their original wording.

The current model is defined by ADR 0007–0010 on top of blueprint §2. The values below are quoted from those decision records; the registry and scenario file are the source of truth.

**Schemes:**

| Scheme | Crop, method | Area | Gross depth | β | Wells |
|---|---|---|---|---|---|
| A, Upper Citrus Estate | citrus, drip | 625 ha | 1,000 mm | 0.90 | deep submersibles; pump-cost factor 1.0 |
| B, Midstream Paddy Cooperative | flooded rice | 900 ha | 1,000 mm | 0.60 | shallow smallholder wells, fail at B ≤ B_low; factor 1.8 |
| C, Tail-end Wheat Farms | winter wheat, sprinkler | 400 ha | 850 mm | 0.75 | factor 1.5 |

**River:**
- inflow cards wet / normal / dry: 22 / 17 / 12 Mm³;
- reserve 2;
- deck of 1 wet, 3 normal, 2 dry cards; game length T of 5 or 6;
- deck order and T sealed by SHA-256 commitments and revealed at the end.

**Aquifer:**
- full = B₀ = 20 Mm³;
- B_low = 15 (the 8 m suction limit);
- B_res = 10;
- κ = 0.1;
- natural gain G(B) = min(r₀, κ·(B₀ − B_observed)), and the river loses the same G next season (capture-consistent, ADR 0009);
- spill above full goes to the river below the schemes' off-takes;
- 60 % of return flow recharges the aquifer.

**Pumping:**
- each scheme's cap is 0.5 × its demand;
- cost = factor × (2 + 0.8·(1 − B/B₀)) per Mm³ (lift energy);
- requests are rationed pro rata when the stock above B_res runs short.

**Actions:**
- Orchard (once): switch to citrus at the scheme's own area and method.
- Drip (once): consumption × 0.95, diversion = consumption / 0.90.
- Expand (repeatable): × 1.2.
- Which scheme may play which action follows its irrigation method: A may only Expand; B may play Orchard or Expand; C may play any.

**Lenses enabled in v1.0:**
- utilitarian (value-maximising; ties broken by leximin adequacy);
- strict egalitarian;
- proportional;
- capability;
- sufficientarian, whose shortfall rule is chosen by a table vote (ADR 0003).

Weighted utilitarian, prioritarian, equal sacrifice and Talmud are implemented in the solver but disabled in the scenario until v1.1.

**Scoring:**
- **Dials:**
  - E_PJ (fair shares of need);
  - E_SE (equal amounts per claimant, per hectare or per person);
  - F (productivity, consumed or diverted);
  - S, sustainability: ΣβW plus the non-recharging share of the return flow, divided by allocable water plus G.
- **Collective score:** the mean of the seasons' geometric means. The score is itself a lens, close to ∛E_PJ (ADR 0010).
- **Livelihood points** per scheme.
- **Survival floor:** A < 0.5 strictly. Two such years running raises the flag "below the survival floor two years running"; the record field is still named `cropFailure`.
- **Private goals** (R15).
- **Two-line verdict:** the rule voted versus the rule the outcome best satisfied.

**Information (ADR 0004 and its amendments):**
- **During play the table sees:**
  - the dials computed on the public allocation;
  - the sustainability band word only;
  - the tank level rounded to 1 Mm³;
  - total pumping rounded half up to 1 Mm³.
- The exact values are sealed.
- The private preview shows harvest and points only up to the pumping the observed tank guarantees (E11).
- **At the debrief**, per-scheme figures open only if the table chooses (`debrief.opened {perPlayer}`). Otherwise everything computed on actual use stays sealed.

## 5. The Season Record (as implemented)

**Visibility classes:**

| Class | Who sees it |
|---|---|
| `public` | everyone |
| `self` | the acting role; everyone after a per-player debrief |
| `sealed` | per-player debrief only |
| `mixed` | public and sealed parts in one payload |
| `server` | no projection, ever (ADR 0011) |

**Event types emitted today:**
- `game.created`, `player.joined`, `research.consent`;
- `season.climate`, `lens.proposed`, `lens.voted`, `lens.vetoed` (ADR 0015), `lens.tied`, `lens.chosen`, `lens.floorVoted`, `lens.floorRule`;
- `allocation.issued`, `private.opened`, `action.played`;
- `season.resolved`, `tutorial.resolved`;
- `game.timeboxed`, `game.ended`, `goal.result`;
- `debrief.opened`, `debrief.welfare`, `review.answer`.

**Intents (`_on_*` in `record.py`):**
- `join`, `start_tutorial`, `start_season`;
- `propose` (Authority only, R7; issue #34, 2026-10-15), `vote`, `veto` (Authority, once per game, then a re-vote of the remaining lenses only; ADR 0015), `close_vote`, `break_tie`;
- `floor_vote`, `close_floor_vote`;
- `commit` (with `autoCommitted` when the phone's own timer fired), `timebox`, `open_debrief`, `review_answer`;
- `timeout_private`, from the server's private-turn timer only (actor `engine`, not in the client protocol; ADR 0013);
- `timeout_vote`, from the server's negotiation timer only (actor `engine`; ADR 0014).

**Timeout marks (ADR 0013):** a timer's commit carries `autoCommitted: true` and `autoCommittedBy` (`phone` or `server`) on `action.played`. `project` withholds both from every viewer, the scheme itself included, until a per-player debrief.

**Properties:**
- `audit(setup, events)` recomputes every season and checks the commitments; an empty list means verified.
- Replay is byte-exact.
- Blueprint §6.2's event table is generated from `record.py`, the source of truth (maintainer, 2026-10-15): event, permitted role (from each handler's `actor` checks), visibility, and payload fields one level deep. After changing an `_emit` call, run `uv run python scripts/generate_event_table.py` in `packages/engine-py`; `tests/test_event_table.py` fails until you do. Planned events sit in a hand-written "Not yet emitted" list below the table; move a row out of it when the engine first emits that event.

**Gotchas:**
- **Windows console:** set `PYTHONIOENCODING=utf-8`. The text uses Unicode freely (Mm³, ≥, β).
- **Windows multiprocessing:** run scripts from files with an `if __name__ == "__main__":` guard, not from stdin.
- **Line endings:** git normalises to LF; CRLF warnings on Windows are expected.
- **Rounding:** the engine rounds every number to 1e-6 at the event boundary (§7.2). Tests compare to the printed precision of the blueprint value.
- **TS mirror ties:** the mirror refuses utilitarian ties it cannot break the way Python does (`TIE_DIGITS`) rather than return a different optimum.
- **Public field names:** avoid sealed key names (`pumpsTotal`, `W`, `A`, `Y`, `dL`, `P`, …) in public payloads. Privacy tests scan every message for them.
- **UI tables:** the debrief has two tables. Query them by accessible name (`getByRole('table', { name: /Each scheme/ })`).
